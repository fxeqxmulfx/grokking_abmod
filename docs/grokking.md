# Grokking on Mesh GPT

`mesh-gpt grok` implements the modular arithmetic experiment from
[Grokking: Generalization Beyond Overfitting on Small Algorithmic Datasets,
arXiv:2201.02177v1](https://arxiv.org/abs/2201.02177v1) on the existing Mesh GPT.
The experiment measures whether validation accuracy improves long after training
accuracy saturates. A successful short training run establishes that gradients
and updates work; observing grokking requires a much longer run.

## Run

```bash
# One complete epoch: 4704 training equations, nine batches of 512 and one of 96.
cargo oxide run --bin mesh-gpt -- grok \
  --epochs 1 --report-every 10 --output target/mesh-gpt-grokking-epoch

# The paper's usual 100000-update budget; training continues after perfect accuracy.
cargo oxide run --bin mesh-gpt -- grok

# Modular division, excluding division by zero.
cargo oxide run --bin mesh-gpt -- grok \
  --operation div --train-fraction 0.5 --seed 7 --epochs 10000 \
  --output target/mesh-gpt-grokking-div

# Learning curves and a PCA view of the shared generated vectors.
uv run --locked scripts/plot-grokking.py target/mesh-gpt-grokking-epoch

cargo oxide run --bin mesh-gpt -- grok --help
```

The default task is addition modulo 97. The full table has 9409 ordered pairs;
a seeded random split places 4704 in training and 4705 in validation. The split
stays fixed throughout a run. A separate seeded permutation assigns abstract
token IDs to residues, so fixed token codes do not expose the numeric ordering.
Every residue, operator, and equals sign occupies one token. Inputs are four
tokens `[a, operator, b, equals]`; only the answer at the final position contributes
to loss or accuracy. Earlier positions still receive gradients through attention.
`IGNORE_TARGET` masks their next-token losses. Loss is divided by the number of
supervised answers, including in short final batches.

Minibatches traverse a shuffled training set without replacement. A short final
batch completes each epoch before the next shuffle. Validation equations never
enter the sampler. Every report evaluates both entire splits and records their
cross-entropy and answer accuracy, rather than an estimate from sampled batches.
`--epochs N` ends after exactly `N` complete passes and includes each short
final batch. It is mutually exclusive with an explicit `--steps` budget.
`--stop-validation-accuracy X` ends training earlier, at the first report whose
complete validation split reaches accuracy `X`. That report's checkpoint,
embeddings and predictions are the final artifacts. Without the flag, training
uses the whole budget.
For division modulo 97 with a 50% split and batch 512, each epoch has 4,656
equations and ten updates, so 10,000 epochs is 100,000 updates. Each CSV
observation records examples seen, complete epochs, and partial-epoch progress.

## Tasks and optimization

All arithmetic below is modulo the chosen prime `p`, which must be in `2..254`:

| Operation | Target |
| --- | --- |
| `add` | `a + b` |
| `sub` | `a - b` |
| `div` | `a / b`, with `b != 0` |
| `mixed` | `a / b` for odd `b`, otherwise `a - b` |
| `square-sum` | `a² + b²` |
| `quadratic` | `a² + ab + b²` |
| `quadratic-linear` | `a² + ab + b² + a` |
| `cubic-product` | `a³ + ab` |
| `cubic-mixed` | `a³ + ab² + b` |

Defaults follow the usual optimization settings in Appendix A.3: AdamW learning
rate `0.001`, weight decay `1`, betas `(0.9, 0.98)`, epsilon `1e-8`, a linear warmup
over the first 10 updates, batch size `min(512, floor(training_size / 2))`, and
100000 updates. Reports occur every 1000 updates and at the final update. The
paper's million-update modular-division figure used Adam without weight decay;
that is a different setting from these defaults. To study sensitivity, use
separate output directories for different seeds and training fractions.

## Mesh architecture and scope

The default model has two blocks, width 128, four heads, context four, embedding
and attention mesh depth four, and feed-forward mesh depth six. Its **12288
learned parameters are all mesh edges**. The input embeddings and output head
share vectors generated by the embedding mesh. All projections are bias-free;
all RMSNorms are parameter-free. XSA, pre-RMSNorm, per-head QK-Norm, and full-head
slice RoPE always run, as in the existing model.

Grokking runs accept widths up to 1,024 using the same specialized kernels
as the benchmark. Widths up to 128, 512, and 1,024 select their respective
tensor capacities. Layer count and mesh depths remain runtime settings.
For example, width 1,024, five blocks, attention depth eight and feed-forward
depth sixteen have 507,904 learned parameters. This describes capacity;
successful generalization must still be measured.
Evaluation uses chunks of 128 equations by default; `--eval-batch N`
adjusts their memory footprint while still evaluating every equation.
`--init-gain X` scales all initial mesh edges before the first update,
including each projection's final layer. The default is one and preserves
the original seeded initialization. This permits an explicit initialization
search for deeper meshes without changing their connectivity or operators.
`--embedding-output-gain X` additionally scales only the embedding mesh's
final linear layer. It scales both the input embeddings and tied output head
at initialization, independently of the other projections. Its default is one.
`--qk-signs 1` multiplies each final Q/K mesh row by an independent seeded
sign. A separate SplitMix64 stream leaves the base initialization, dataset
and sampler unchanged. This varies the initial Q/K directions while retaining
all mesh connections; the default is zero.
`--embedding table` and `--connectivity butterfly` select the ablations in
[Mesh GPT](mesh-gpt.md#ablation-variants). A table replaces the embedding mesh
with learned tied token vectors; butterfly meshes read channel
`c + 2^(layer mod floor(log2 width))` instead of `c + 1`. The gains and Q/K signs
above first adjust the mesh-embedding initialization. A table then stores the
vectors generated by that adjusted mesh, so `--embedding` changes the
parameterization but not the initial model. `run.txt` records `embeddings`,
`mesh_connectivity` and `embedding_parameters`.
`--embedding-init-unit` normalizes every table row once after the initialization
gains, including the operator and equals sign. It requires `--embedding table`,
`--embedding-norm none`, and no protected features. The table then trains
without a norm constraint. This differs from `--embedding-norm unit`, which
normalizes the effective input and output vectors at every forward pass.
`run.txt` records the one-time policy as `embedding_init_unit`.
`--workspace-cache 3` retains the full training batch, short tail and evaluation
batch buffers, avoiding repeated device allocation. It uses more GPU memory;
the default retains one training batch shape. Every inference and update still
recomputes activations from current weights.

The paper used a dense Transformer with approximately 400000 non-embedding
parameters. This implementation carries its modular tasks and training protocol
over to the mesh architecture; it does not reproduce that dense model or the
paper's separate permutation-group tasks. Mesh capacity and channel connectivity
can change how much data or optimization is needed for generalization. Neither
perfect training accuracy nor an embedding plot alone establishes grokking.

## Artifacts and checks

The output directory contains:

- `run.txt`: task, split sizes, seeds, model and optimizer settings, total examples
  seen, completed epochs, elapsed time, and first recorded steps with 99% accuracy.
  A threshold that was not reached is recorded as `not_reached`. It also records
  `stop_validation_accuracy`, `completed_steps` and `stop_reason`:
  `validation_accuracy` or `update_budget`.
- `loss.csv`: step-zero and subsequent complete-split metrics, examples seen,
  completed epochs, partial-epoch progress, weight L2 norm, learning rate,
  and elapsed time.
- `equations.csv`: the exact split, numeric labels, and input/target token IDs.
- `symbols.csv`: the residue-to-token mapping, operator, and equals sign.
- `model.bin`: `MSHGPT07` weights (`MSHGPT08` for ablations) and the exact
  abstract-symbol tokenizer. Private-use
  Unicode characters encode residue identities for checkpoint round-trips; CSVs
  give their numeric labels. Checkpoints contain weights rather than AdamW state.
- `initial-model.bin`: the step-zero checkpoint, before any optimizer update.
- `initial-embeddings.csv`: effective tied vectors at step zero, including
  geometry transformations and any one-time table normalization.
- `embeddings.csv`: shared token vectors after training: mesh outputs or table rows.
- `predictions.csv`: final answers, correctness, and answer loss for every equation
  in both splits.

The plot script requires NumPy and Matplotlib. It produces standalone SVG and PNG
learning curves and embedding plots. The embedding view uses PCA, with colors
for residues modulo eight and lines for adding eight; the paper's visualization
used t-SNE. Any visible structure should be checked against held-out accuracy.

```bash
cargo test --all-targets --locked
cargo clippy --all-targets --locked
cargo oxide run --bin mesh-gpt -- verify
```

CPU tests cover complete, disjoint, reproducible operation tables, abstract symbol
IDs, prime and split validation, equation masks, without-replacement epoch
sampling, and gradients against finite differences. CUDA verification compares
masked and unmasked losses and every parameter gradient against independent f64
autodiff, including width 128 and batch tails. It checks AdamW continuation and
reset under both beta2 `0.999` and `0.98`.

The one-epoch command above on an RTX 3050 Laptop GPU produced training
cross-entropy `7.41967 -> 6.53287` and validation cross-entropy
`7.43258 -> 6.54729`. All 4704 training equations were used exactly once, and
both complete splits were evaluated. Answer accuracy remained zero after these
10 warmup updates, so this establishes a working loss descent rather than
successful generalization or grokking.

A separate 1000-update smoke run with the default width-128 mod-97 model ended
at training cross-entropy `4.58679` / accuracy `1.28%` and validation
cross-entropy `4.59957` / accuracy `0.83%`. These results are near chance and do
not establish grokking. CUDA optimization preserves the model and training
protocol; it does not imply successful generalization of this mesh architecture.
